# matchwatch Faz 1 — Go Çekirdek Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** UBL-TR e-Fatura/e-İrsaliye yükleyen, sözleşme (JSON) ile SKU bazlı 3-way eşleştiren, tüm deterministik anomali kurallarını çalıştırıp bulguları kanıtıyla saklayan, multi-tenant (RLS) bir Go REST API.

**Architecture:** `ubl` XML'i parser struct'larına çevirir; `repository` bunları PostgreSQL'e yazar ve denetim girdisini `domain` tiplerinde yükler; `matcher` ve `anomaly` saf (DB'siz) fonksiyonlardır; `audit` servisi tek bir tenant transaction'ı içinde yükle → eşleştir → kuralları çalıştır → yaz akışını yönetir; `transport/http` bunu REST olarak sunar (Faz 3 Vue paneli bu API'yi tüketecek).

**Tech Stack:** Go 1.23+ (yerelde 1.26 kurulu), `github.com/shopspring/decimal`, `github.com/jackc/pgx/v5` (+`pgxpool`), `github.com/google/uuid`, `github.com/golang-jwt/jwt/v5`, standart `net/http` ServeMux (method pattern'li), `encoding/xml`, PostgreSQL 16 + pgvector (`pgvector/pgvector:pg16` imajı), Docker Compose.

**Spec:** `docs/spec.md` — özellikle §3 (kurallar) ve §4 (Kararlar D1–D13; orijinal spec'le çelişirse D'ler geçerli).

## Global Constraints

- Para, miktar, oran için hiçbir yerde `float32`/`float64` yok (testler dahil). Go'da `decimal.Decimal`, DB'de `BIGINT` kuruş veya `NUMERIC`.
- Kuruşa çevirme tek yerden: `domain.ToMinor`, half-away-from-zero (`decimal.Round(2)`).
- Birim fiyatlar `NUMERIC(19,6)`; miktarlar `NUMERIC(19,4)`; oranlar `NUMERIC(5,2)`; toplamlar ve `financial_impact_minor` `BIGINT`.
- Kural motoru ve eşleştirici DB'ye veya ağa dokunmaz (saf fonksiyon); LLM yok.
- Her bulgu `evidence_json` içinde en az fatura `line_id` (XML `cbc:ID`) taşır; sözleşme kaynaklı bulgular ayrıca `contract_no`, `source_page`, `source_clause_text` taşır.
- Uygulama DB'ye yalnızca `matchwatch_app` rolüyle bağlanır; her tenant sorgusu `Store.InTenant` içinde çalışır.
- Go module yolu: `github.com/bengin-noyan/matchwatch/backend-go`. Kod `backend-go/` altında, compose/Makefile repo kökünde.
- Entegrasyon testleri `MATCHWATCH_TEST_DATABASE_URL` (app rolü) ve `MATCHWATCH_TEST_MIGRATE_URL` (owner rolü) yoksa `t.Skip` eder; `make test-integration` bunları compose DB'sine ayarlar.
- JSON'da decimal değerler string (`"1.250000"`), kuruş değerleri integer.

## Review Focus

1. **Başka şirkete kesilmiş fatura yüklenmesi** (AccountingCustomerParty VKN ≠ tenant VKN) → 422, kayıt yok. Test: Task 10.
2. **Aynı irsaliye miktarının iki faturada kullanılması** (sıralı veya eşzamanlı denetim) → ikinci fatura `QTY_EXCEEDS_DELIVERY` alır; aday irsaliye satırları `FOR UPDATE` ile kilitlenir. Test: Task 9.
3. **Fatura irsaliyeden önce gelirse** → irsaliye/irsaliye yanıtı yüklendiğinde ona referans veren faturalar otomatik yeniden denetlenir ve RED→GREEN olabilir. Test: Task 10.
4. **Hizmet faturası (irsaliyesiz)** → sözleşmesiz ve irsaliye referansı olmayan satırda miktar kuralı çalışmaz; sahte kırmızı yok. Test: Task 7.
5. **Sıfır/negatif miktar, eksik ETTN, satırsız fatura, bozuk XML** → parser hata döner, API 422; hiçbir yolda panic (sıfıra bölme) yok. Test: Task 3, Task 10.
